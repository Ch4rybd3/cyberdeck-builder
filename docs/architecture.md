# Architecture

## Stack

| Layer | Choice |
|---|---|
| UI | React 18, TypeScript, Vite, Tailwind CSS |
| Design system | Remora tokens and primitives: four themes, a four-size type scale, hairline panels, one accent |
| State | Zustand: one store for the open build, undo history and library; one for derived geometry |
| Storage | IndexedDB (`idb-keyval`), local-first |
| 3D view | three.js via @react-three/fiber and drei |
| Geometry | Manifold (WebAssembly) for booleans, run in a Web Worker; custom STL and 3MF writers |
| Diagrams | @xyflow/react |
| Validation | Zod schema with versioned migrations |
| Routing | Hash router, so the app runs on any static host |

## Data flow

```
Build (JSON, schema v1)
  ├─► geometry/caseBuilder ─► pieces (meshes per colour) ─► viewport, 3MF/STL, BOM, checks
  ├─► domain/power ─────────► rails, autonomy ─────────────► Power page, checks, wiring
  ├─► domain/ports ─────────► port assignments ────────────► checks, wiring
  ├─► domain/wiring ────────► wires ───────────────────────► Wiring page, BOM (wire)
  └─► domain/constraints ───► ranked issues ───────────────► Checks
```

Everything shown is **derived** from the Build. The Build is the only thing stored.

The case generator runs in a **Web Worker** (`src/geometry/worker.ts`). Only the newest pending change is generated, so a fast drag never queues up stale rebuilds. If workers are unavailable, it falls back to the main thread.

Custom components live in the Build (`customComponents`). Every derived function calls `syncCustomComponents(build)` first, so `componentById` resolves them anywhere, including inside the worker.

## Source layout

```
src/
  catalog/      components, templates, example builds
  domain/       schema, migrations, layout maths, power, ports, wiring, constraints, BOM, DeckPort, hardware, printers
  geometry/     Manifold loader, case generator, exporters
  store/        build store (undo, IndexedDB), geometry store
  ui/           design-system primitives and icon registry
  layout/       app shell and navigation
  pages/        one file per page; workshop/ holds the Workshop's parts
docs/           this documentation (rendered in the app)
```

## Conventions (from Remora)

1. **English only**: code, comments, UI strings and docs.
2. **No literal colour outside the token file.** Use semantic CSS variables, so every theme keeps working. Filament colours are user data and are exempt.
3. **One icon per concept**, imported from `src/ui/icons.ts`.
4. **A schema change ships with its migration.**

## Documentation screenshots

The images in `docs/images` are generated by `scripts/screenshots.mjs`, which drives the dev server with headless Chromium through a development-only hook (`window.__cdb` in `src/main.tsx`):

```sh
npm run dev
APP_URL=http://localhost:5173 npm run screenshots   # CHROME_PATH=/path/to/chromium if needed
```

Regenerate them whenever the interface changes.

## Checks

`npm run check` runs ESLint (including the icon rule), TypeScript and the Vitest suite. CI (`.github/workflows/ci.yml`) runs the same steps plus a production build on every push and pull request.

## Deployment

`npm run build` produces a static site in `dist/` with relative asset paths. The GitHub Actions workflow in `.github/workflows/pages.yml` deploys it to GitHub Pages. It is manual (`workflow_dispatch`) until the site goes live. The same build works on a custom domain.
